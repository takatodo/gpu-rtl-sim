## Objective

Move FC-063 from synthetic LLVM IR fixtures to a small reproducible corpus gate
using real or generated lowered LLVM IR samples. The gate should prove that the
suitability analyzer can be run on representative frontend output without
weakening the claim boundary.

The desired operator question is:

```text
Given this lowered RTL LLVM IR, should the next implementation attempt use
state-parallel GPU execution, CPU-parallel orchestration, or a materially new
implementation / GEM-like mapping?
```

This issue is still analysis-only. It must not execute RTL, launch GPU kernels,
change runtime ABI, or claim speedup/usefulness.

## Scope

- Add a reproducible corpus runner or focused contract fixture that invokes the
  FC-063 analyzer on at least one state-parallel known-good sample and one
  VeeR/design-CPU-like poor sample.
- Prefer checked-in compact IR fixtures only when they are small and
  hand-reviewable. Large generated IR must stay under `artifacts/` or
  `reports/` and be regenerated by documented commands.
- Keep the JSON output as review/debug metadata, not execution authority.
- Verify that realistic LLVM function names, including dotted or quoted names,
  remain accepted through `--entry`.
- Verify that missing entry, unsupported atomics/fences, volatile memory, inline
  asm, or observable-heavy CPU-core patterns fail closed or classify poor.

## Acceptance

- The corpus gate runs the analyzer on a state-parallel lowered IR sample and
  records `good_state_parallel` / `gpu_state_parallel`.
- The corpus gate runs the analyzer on a VeeR/design-CPU-like lowered IR sample
  and records `poor_requires_new_implementation` /
  `cpu_parallel_or_gem_like_mapping`.
- The report or test assertions include `branch_density`,
  `memory_regularity_score`, `state_independence_score`, and
  `observable_pressure`.
- Dotted/quoted LLVM symbol names are covered by the real-corpus path or by an
  adjacent focused fixture.
- Generated reports do not contain local absolute paths.
- Documentation says the corpus gate is static suitability evidence only, not
  correctness equivalence, GPU execution, timing, runtime ABI, speedup, or
  RTLMeter usefulness evidence.

## Current State

- `tests/contract/test_llvm_rtl_gpu_suitability_cli.py` now includes a compact
  lowered-IR corpus gate that invokes the public CLI with `--write-report`.
- The corpus gate also regenerates one state-parallel LLVM IR sample from a
  temporary C++ source with `clang++ -S -emit-llvm -O1`, then runs the public
  analyzer CLI against that generated `.ll` file. The generated IR remains a
  temporary/generated artifact, not source of truth.
- That regenerated sample now uses the existing
  `build_vl_gpu_compile.compile_ll` helper, keeping the gate closer to the
  repository `build_vl_gpu` LLVM IR emission path without committing generated
  `.ll`.
- The state-parallel corpus sample uses a realistic quoted Verilator-style entry
  name and records `good_state_parallel` / `gpu_state_parallel`.
- The VeeR/design-CPU-like corpus sample uses a realistic quoted Verilator-style
  entry name, branchy control flow, observable calls, and volatile stores, then
  records `poor_requires_new_implementation` /
  `cpu_parallel_or_gem_like_mapping`.
- FC-063 analyzer metrics now include defined callees reachable from `--entry`,
  so thin entry wrappers do not hide helper-level branch, observable, or
  volatile pressure.
- FC-045 policy integration now consumes the resulting suitability JSON through
  `src/tools/gpu_sidecar_eligibility_policy.py` as debug/review metadata and
  emits conservative `recommended_action` values without turning JSON into
  runtime ABI.
- The corpus test asserts required metrics and checks stdout plus generated JSON
  for local absolute paths.
- `README.md` documents the `--write-report` corpus-gate usage and repeats that
  reports are generated static suitability evidence only, not execution
  authority or source of truth.

## Non-Goals

- No GPU execution by this issue alone.
- No runtime ABI change.
- No correctness equivalence claim.
- No RTLMeter speedup or usefulness claim.
- No broad arbitrary RTL support claim.
- No large generated LLVM IR committed as source of truth.
